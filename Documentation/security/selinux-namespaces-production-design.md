# SELinux namespaces: production design and selection record

## Status and scope

This document is the persistent decision record for completing SELinux
namespaces.  It is intentionally stricter than a proof-of-concept: every
supported operation must retain label provenance, enforce every policy in the
namespace ancestry, preserve the host's authority, and have bounded resource
use.  Unsupported combinations must fail closed during setup; they must never
silently fall back to the initial or current SELinux state.

The design is developed in audit/implementation cycles.  At the start of each
cycle this document is re-read, findings are added to the open-problems table,
and the selected solution is checked against the invariants and complexity
requirements below.

All design, implementation, and validation work is performed first in the
complete Linux 7.2 development tree at
`kernel-ports/selinux-kernel`.  The lab's current SUSFS kernel source resolves
through `kernel-ports/cachyos-susfs/kernel-env.sh` to
`/home/lucas/.local/share/waydroid-root-lab/kernel/cachyos-kernel-source/source`.
That production source is a read-only migration target until every gate in
this document is satisfied in the development tree.  Migration is a separate
final phase followed by a fresh build and regression audit; partial work must
not be copied there.

## Non-negotiable invariants

1. **Host monotonicity.** A child can only add restrictions.  It cannot choose,
   modify, or forge the label seen by an ancestor.
2. **Explicit provenance.** A durable security label identifies its origin
   domain.  A naked SID is not sufficient at a namespace boundary.
3. **Independent resolution.** Subject label, target label, object class, and
   permissions are resolved for each policy in the credential ancestry.  All
   policies must allow the operation.
4. **View continuity.** A path/mount selects a label view.  A durable object
   (`file`, VMA, asynchronous request, socket, XFRM object, packet metadata,
   key, perf event, IPC object, or InfiniBand object) retains that view or an
   equivalent provenance token for pathless checks.
5. **Parent-owned boundaries.** A parent creates and seals each parent-to-child
   label map before exposing the boundary to the child.  Maps are immutable;
   an update creates a new generation.
6. **Fail closed.** Missing, ambiguous, stale, or unsupported translations are
   rejected.  No object-driven or asynchronous path may use
   `current_selinux_state` as an accidental authority.
7. **Bounded lifetime and accounting.** States, domains, labels, views, maps,
   cache entries, policies, AVCs, and audit traffic have refcount/RCU-safe
   lifetime and enforceable quotas charged to the owning user namespace.
8. **Auditable denial.** The host receives a complete superset of events.  A
   child may receive a filtered mirror but cannot suppress, consume, or flood
   away the host record.  The event identifies the exact denying policy and
   label provenance.

## Terminology and object model

The phrase "per-mount label" is shorthand only.  The mount selects a view; the
view must subsequently be propagated to every durable object used by a
pathless operation.

* `selinux_label_domain`: stable, refcounted provenance domain.  It identifies
  the SELinux state/boundary that owns the meaning of a label.  It is smaller
  and longer-lived than a policy state: durable labels retain the domain, not
  policy/AVC memory.  IDs saturate rather than wrap, preventing ABA.
* `selinux_label_ref`: stable, refcounted reference to a canonical context plus
  its origin domain and generation.
* `selinux_label_assertion`: a label reference plus the mechanism that supplied
  it (xattr, genfs, mount context, NetLabel, XFRM, secmark, or kernel initial
  label).  The source is metadata, not automatically part of context equality.
* `selinux_label_view`: immutable, refcounted projection selected by a mount or
  another security boundary.  It references a sealed boundary map.
* `selinux_label_map`: immutable directional mapping owned by the parent of a
  boundary.  Parent-to-child maps project parent-origin objects into the child;
  child-to-parent maps project child-origin objects into the parent.  Neither
  direction is inferred from the other because many-to-one maps are valid.
  Nested mappings compose through the least common ancestor.

The SELinux object class is deliberately **not** part of canonical label
identity.  A context can label objects of different classes.  Class and
requested permissions are inputs to a policy decision and may need separate
resolution for each policy.

## Selected filesystem architecture

```text
path + mount
    selects immutable label view
        -> open file security blob retains view
        -> VMA/io_uring/SCM_RIGHTS retain or derive from that file
        -> target label is projected separately for every policy
        -> child and every ancestor must allow
```

The inode retains its intrinsic canonical label.  It does not contain a
state-to-SID map.  Different aliases of the same inode can therefore use
different views without duplicating or mutating the inode label.

The superblock owns the interpretation of intrinsic labels.  Before
`SE_SBINITIALIZED` is published, its security blob must acquire one immutable
origin anchor containing a strong SELinux state reference and that state's
label domain.  Delayed inode initialization, xattr parsing, genfs lookup,
label-generation policy capabilities, `kernfs` labeling and raw on-disk
context rendering use a snapshot of this anchor, never the ambient task.
Reusing an existing superblock through a second mount is allowed only when the
requested origin is identical or explicitly compatible.  A mount view
projects the anchored intrinsic label for an observer; it does not change the
origin that owns the bytes stored by the filesystem.

Creation and relabel are sealed transactions, not independent hook calls.  A
prepare operation captures one mount view and one consistent snapshot of every
policy in the credential chain, resolves the directory and superblock labels,
derives the candidate label independently at every depth, chooses the
canonical label in the superblock origin domain, and proves that all projected
labels agree with the per-policy result.  It authorizes directory search/add,
object create, transition and filesystem associate in that same generation.
The resulting plan owns the exact canonical label and origin-rendered xattr
bytes until the VFS either commits them with the new inode or aborts.  Relabel
additionally reverse-resolves an observer context through the sealed
child-to-parent maps and validates `RELABELFROM`, `RELABELTO`, transition and
associate at every depth before replacing the filesystem value.  Context
reads carry the selecting mount/view to the LSM and render the projected label
for that observer.  These operations are Theta(d), the minimum possible when
all d policies must authorize; map and AVC operations remain expected O(1).

Bind/clone semantics are explicit: a clone shares a view by default; deriving
a new view is a privileged parent operation that creates a new immutable view.
Mount propagation, `move_mount`, `pivot_root`, overlay copy-up, and unmount must
transfer or retain references without changing their meaning.  Overlay copy-up
uses the destination layer's intrinsic label domain while retaining auditable
provenance of the source assertion.

### Pathless objects and sealed projections

Objects that have no stable pathname authority cannot borrow an internal
pseudo mount as their creator view.  File-like objects may retain a leaf
compatibility SID in an inode; non-inode objects may retain one in their
subsystem blob.  In either case, the authoritative identity is an immutable,
refcounted `selinux_pathless_projection` captured before the object is exposed.
The projection owns the canonical label and creator view and contains one
16-byte seal per policy depth:

```text
{ domain_id, resolved_sid, resolved_class, label_model, reserved }
```

Construction validates the complete root-to-leaf credential/state/domain
topology, resolves the immutable view exactly once in Theta(d), and proves the
expected SID, class, and label model at every depth.  A later authorization
indexes the seal by the policy domain's bounded depth and verifies its
non-reused domain ID in O(1); authorizing every independent policy is therefore
Theta(d), not Theta(d squared).  Missing, incomplete, same-depth sibling, or
stale topology fails closed.  The only domain-independent bootstrap is an
explicit kernel-global initial label whose exact SID is identical at every
depth.

The generic LSM `file_init_security_anon` finalization hook runs after an
anonymous file's flags, seals, private data, and release path are complete but
before publication.  Unique `anon_inode_create_*` objects, `memfd`,
`secretmem`, and KVM `guest_memfd` invoke it.  SELinux publishes matching
strong references in the inode and file
security blobs atomically with the final leaf tuple; a context-copy object
retains the context inode's already-published projection instead of inventing
a mount view.  Relabel and invalidation paths cannot mutate a published
projection.  File permission, mmap, ioctl, kernel-load, `io_uring` command,
SCM/Binder transfer, and later FD use consume the file/inode projection rather
than reinterpreting the compatibility SID.

## Candidate selection record

| Candidate | Correct for aliases/nesting | Host monotonic | Hot-path complexity | Selection |
|---|---:|---:|---:|---|
| One SID per inode | No | Partial | O(1) | Rejected: cannot encode distinct mount views |
| State-to-SID map in every inode | No | Partial | O(1) average lookup, O(n) memory per inode | Rejected: wrong ownership and unbounded multiplication |
| Inner/outer fields in superblock | Only one boundary | Yes | O(1) | Rejected as final design; acceptable only as a private-superblock compatibility path |
| Mutable boundary maps | Yes | Weak | O(1) average | Rejected: races, stale-cache ambiguity, and child influence |
| Immutable view + sealed maps + per-policy resolution | Yes | Yes | O(1) aggregate hit; O(d) miss; O(1) amortized translation | **Selected** |
| Filesystem clone per container | No shared-volume semantics | Yes | O(1) checks, O(filesystem size) setup/storage | Operational fallback, not kernel semantics |

Here `d` is SELinux namespace ancestry depth.  A cold decision is Theta(d)
because each independent policy must authorize it.  A correctly keyed
aggregate cache may make a hot decision O(1) without skipping policies because
the cached result already represents the whole chain.  Within each level,
translation and AVC lookup must be O(1) expected time using immutable IDs and
bounded hash tables; policy reload may perform descendant invalidation and
entry reclamation off the hot path.

## Cache and reload rules

A cached decision or resolved target must be bound, directly or through stable
aggregate IDs, to:

* subject and target label identities and provenance domains;
* label-view ID and generation;
* boundary-map generation;
* SELinux state/policy identity and policy sequence number;
* the policy initialization phase and the state's descendant `chain_epoch`;
* resolved object class and requested permissions.

Maps are never modified in place.  Policy or map replacement publishes a new
generation and old objects remain readable under RCU until the last reference
is released.  A lookup is O(1) expected.  Walking all ancestors remains O(d).
Cache memory is bounded per state/domain and globally; eviction is O(1)
amortized and cannot invalidate a live reference.

During migration from naked `u32` blobs, a global SID is accepted only as an
opaque handle to `(origin_domain, canonical_context)`.  Context equality alone
does not intern labels from different domains.  Policy-produced initial SIDs
are also interned with their domain; only entries explicitly created in the
kernel-global domain retain universal initial-SID semantics.  A cross-domain
lookup without a sealed directional map fails with `-EOPNOTSUPP`.  The bridge
has owner/global quotas, non-reused tombstones and RCU-reclaimable payloads.
It is still not the final storage layer because every non-initial SID retains
a compatibility baseline reference until the remaining scalar-only consumers
are converted and the live lifetime matrices pass.  Supported durable families
now retain either a refcounted `selinux_label_ref`, an immutable view, or a
sealed pathless/network projection while keeping numeric SIDs only as ABI or
compatibility mirrors.  Superblocks retain canonical global handles and are
projected dynamically through the actual mount view, or through a temporary
identity view when no mount exists.  Mechanical reclamation and accounting are
validated; removal of the general baseline and live teardown evidence remain
production gates.

Each state has a `chain_epoch` used by O(1) file and aggregate-cache fast
paths.  A policy/enforcing change increments the epoch of that state and its
descendants in O(number of descendants), outside the authorization hot path.
A normal epoch comparison remains O(1).  The counter saturates at a zero
sentinel before signed wrap; zero is never cache-valid, so an exhausted state
uses the full authorization path permanently instead of permitting an ABA.
This exceptional state is fail-closed and descendant epochs continue to be
updated independently.
A child therefore cannot invalidate the host or a sibling merely by reloading
its own policy.  A single global policy epoch is rejected because it creates a
cross-namespace performance channel and denial-of-service primitive.

## `current_selinux_state` rule

`current_selinux_state` means the state attached to the current credentials.
It is valid only when the hook's security authority is unambiguously the
calling task.  Low-level resolvers accept an explicit state/domain/view.
Asynchronous and object-driven operations derive authority from the durable
object.  CI must reject new ambient-state use in helpers designated
object-driven.

### Namespace construction and activation

`LSM_ATTR_UNSHARE` remains a compatibility operation that can create an
isolated, fail-closed child, but it is not the complete runtime control plane.
The production API creates a dormant namespace represented by an nsfs FD.  A
parent-authorized builder loads the target policy, adds mappings as explicit
context pairs in both directions, and seals every parent/child boundary.  Only
`ACTIVATE` publishes the state/domain/map generation for `JOIN`; no task or
mount can observe a partially configured namespace.  A join validates the
complete chain and reconstructs the credential's local SID and retained parent
credential transactionally.  Merely replacing a `state` pointer is forbidden.

Checkpoint/restore recreates the parent first and verifies policy digest,
policy sequence, contexts, boundary-map generations and stable namespace IDs
before activation.  Namespace-FD get/put is O(1), map construction is O(m) for
m explicit pairs with expected O(1) insertion, and join/restore validation is
Theta(d).  A deferred mount must carry an explicit target namespace FD and
origin anchor.  If that policy is not active, mount publication returns
`-EAGAIN`; a sibling in the same user namespace may never claim it.  This
avoids the existing global O(all-superblocks) first-policy-load scan.

### Resource ownership and audit routing

Every state/domain references a central owner account keyed by its owning user
namespace.  It charges domains, canonical labels, global SID entries and
context bytes, maps and entries, views/projections, parsed and serialized
policies, AVC/xperm nodes and audit traffic, with an independent host-global
hard cap.  Reservation precedes publication and rollback uncharges in O(1).
An AVC over quota computes the decision without caching.  A global SID entry
is live-refcounted: its numeric ID is never reused, but on the final handle the
reverse index, context, label/domain refs and translation cache are reclaimed,
leaving only a small tombstone.  Optimizing network caches store stable domain
IDs and generation cookies, not strong policy-state references; reload is lazy
O(1) invalidation instead of a host/sibling-wide flush.

Authorization and audit are two phases.  The decision phase evaluates every
policy under one consistent chain snapshot with auditing disabled, collecting
all denials; it stops early only for a structural/stale error.  The commit
phase emits a host-owned aggregate event containing stable namespace/domain
IDs, policy sequence, canonical label/domain IDs, assertion source, and
view/map generations.  A child mirror is optional and filtered, while a
hierarchical owner quota plus capacity reserved for `init_user_ns` prevents a
child from consuming the host channel.  If a mandatory host event cannot be
queued, the operation fails rather than silently losing the audit guarantee.
The authorization cost is necessarily Theta(d); route/charge is O(1).

The first implementation deliberately omits the optional child mirror.  The
converted AVC chain helpers copy stable identities before queueing, reserve
the root account's host-only token pool for the exact aggregate size plus
fixed queue overhead, and fail closed on reservation, allocation, audit
availability, rate-limit or enqueue failure.  Legacy LSM callers retain the
void `common_lsm_audit()` wrapper; the mandatory path uses a status-returning
variant.  Direct single-state AVC loops outside those helpers remain an
explicit caller-migration gate.

### selinuxfs state binding and policy bytes

Every policy-dependent selinuxfs file and directory operation rechecks that
the file's superblock-bound state is the current credential state.  This
includes reads, writes, directory iteration, seeks, status/policy mmap setup,
and VMA faults.  Selection and rejection are O(1).  Because a fault check
cannot revoke an already-resident PTE, the current `LSM_ATTR_UNSHARE` path also
requires exclusive ownership of the `mm` and rejects a task whose `mm` contains
a policy/status VMA.  A refcounted rhashtable entry records the number of those
VMAs per `mm`; `vm_ops.open` and `vm_ops.close` cover fork, split, mremap and
unmap, and the transition gate performs an O(1)-expected lookup under the
`mmap_lock` and registry mutex.  Each entry holds an `mmgrab()` pin until an
RCU-delayed worker drops the pin and frees the entry, preventing pointer ABA.
The initial mmap fails if its entry cannot be allocated.  Because a duplicated
VMA's void `open` callback cannot report allocation failure, that VMA receives
an explicit error marker and a global incomplete-tracking counter makes all
namespace transitions fail closed until every such VMA is closed.  Fork
inheritance therefore retains the existing mmap ABI without a VMA scan.  The
incomplete counter uses a permanent baseline `refcount_t`; overflow saturates
instead of wrapping to a value that could be mistaken for complete tracking.

`CONFIG_SECURITY_SELINUX_POLICY_MAX_BYTES` is the hard binary-policy input and
snapshot limit, with a conservative 64 MiB default.  Load size is rejected in
O(1) before `vmalloc`; `policy_mutex` is acquired before allocation and held
until the buffer is freed, bounding staged load input to one configured limit
per state.  Policy snapshots obtain the active serialized length under the
same mutex, reserve that actual length in a superblock-lifetime atomic counter,
and pass the hard limit into `security_read_policy()`, which checks
`policydb.len` before `vmalloc_user`.  Reservation and release are O(1).
Parsed-policy admission is now charged to the state's central owner account
before parsing.  The selected charge is one fixed slot equal to
`CONFIG_SECURITY_SELINUX_POLICY_MAX_BYTES`, rather than the attacker-selected
serialized length: a small input may expand into substantially more parsed
objects, so charging only `len` would permit many cheap reservations followed
by expensive parses.  The fixed slot gives a conservative hard bound with
O(1) reserve/release, charges both old and staged policies during reload, and
is transferred (not duplicated) by a boolean-only policy clone because that
clone shares the non-conditional policy storage.  More precise allocation-site
byte accounting was rejected for this gate because it is invasive, adds a
charge operation to every parser allocation, and does not improve the
asymptotic or safety bound.  Kconfig requires both the per-owner and global
byte budgets to admit at least one maximum-size policy slot; a reload
naturally requires spare capacity for the second, staged slot.  NS=y and NS=n
`W=1` service builds and the Kconfig range check pass with exact source-artifact
restoration.  Audit traffic accounting and mandatory host delivery remain
separate production-gate work.

## Production gates

Completion requires evidence for all of the following, not merely absence of a
known failure:

* parent and child simultaneously enforcing under the full SELinux testsuite;
* sibling and nested namespaces with disjoint policy capabilities;
* bind, clone, propagation, `move_mount`, `pivot_root`, idmapped mounts,
  overlay copy-up, shared volumes, and teardown races;
* ext4/xfs/tmpfs/devpts/proc/sysfs plus explicitly supported network filesystems;
* open FD, `mmap`, `io_uring`, `SCM_RIGHTS`, IPC, keys, BPF, and perf;
* policy reload and map-generation replacement while objects remain live;
* netns forwarding, XFRM, NetLabel, secmark, and peer-label exposure;
* namespace create/clone/join, runtime integration, and checkpoint/restore;
* policy/selinuxfs/map fuzzing and deterministic resource-exhaustion tests;
* proof that a child cannot influence the label or decision observed by the
  host except through a mapping already authorized and sealed by the host.

## Completion rule

An item is closed only when code, focused tests, build results, and the relevant
production gate provide direct evidence.  After each implementation cycle, a
fresh cross-subsystem audit must try to contradict the invariants above.  New
findings are added to the ledger and the cycle repeats until every supported
surface has evidence and every unsupported surface is rejected explicitly.
